# 2026-10-15 아키텍처 반영

초기 다중 호출 CLI를 에이전트 중심의 앱 흐름으로 바꾼 기록이다. 관계 조회에는 [LatticeDB](https://latticedb.org/)를 사용한다. 기본 요청은 모델 최대 1회로 제한하며 생성 결과는 사용자 검토가 필요한 초안으로 제공한다.

## 후속 변경 안내

아래 검증은 초기 v1 기록이다. 후보 비교·선정/배제 근거와 실행 계약을 강화한 현재 `product-one-call.v2.3`의 결과는 [최신 검증 보고서](product-v2-validation.md)를 참고한다. [에이전트 설계](agent-design.md)와 [Langfuse 비용 관측](langfuse.md)을 추가했다. 초기 실패·비용·사용자 상태는 보존했다.

## 검증

- Python 테스트 **255개 + 하위 테스트 18개 통과**.
- React TypeScript 검사와 Vite production build 통과.
- 실제 API로 15개 주제 조회, 리드 검색, 빈 검색, 채널 필터, Q068 원문·인용 ID를 브라우저에서 확인.
- API/store 집중 테스트는 서버 재시작, 고객 격리, 동일 제안 동시 저장, 상태 재활성화 충돌, 404/409/422/503, 미설정 키 fallback을 검사했다.
- DuckDB는 15개 주제 × 2개 스냅샷의 모든 지표 분자·분모를 기존 정제 계산과 대조했다.
- LatticeDB는 실제 인용 경로, 재개방, 버전 불일치, 원본 변경, 동시 접근을 검사했다.

실제 OpenRouter `openai/gpt-5.4`로 4개 초안을 생성했다. 각 요청은 모델 1회이며 구조·근거·측정 검사를 통과했다. 자동화·수집 부족은 호출 0회로 각각 `no_action`·`insufficient_evidence`를 반환했다. [실행 기록](../output/product-live-validation.json).

실제 공급자 보고 비용 합계 **$0.747020**, 과제 환산 호출 원가 **$0.072**다. 동일 4요청 재실행은 모두 캐시 적중으로 추가 호출 0회였다([재실행 기록](../output/product-cache-replay.json)). 이는 지정된 반복 시나리오이며 운영 캐시 적중률 추정이 아니다.

**내용 품질은 4개 모두 통과하지 않았다.** 별도 읽기 전용 검토에서 지원 확인 사례는 새 P1/P2가 없었고, 나머지 3개는 수정이 필요했다([구체적 검토 기록](../output/product-quality-audit.json)). 일반 리드는 보조 전용 문서가 주 자산 후보에도 들어갔다. 미지원 사례는 게시·source ID 등록 조건에 모순이 있었고, 보안 사례는 자산 선택 실패 분기와 “미언급 0/12” 표현이 잘못됐다. 원본 초안은 보존하고 자동 승인으로 처리하지 않는다. 검토 전 저장이나 실행을 권하는 품질 결과가 아니며, 1회 경로가 이전 3~5회 경로의 의미 검토 품질을 유지했다고 주장하지 않는다.

Docker에서도 실제 DuckDB 집계·LatticeDB 조회와 0회 분기를 확인했다. 실제 생성된 초안을 SQLite에 넣고 HTTP로 상태를 변경한 뒤 컨테이너를 재시작해 원문·메모·상태가 유지됨을 확인했다([Docker 기록](../output/docker-product-smoke.json)). 컨테이너 검증용 고객은 `validation`이며 제품 데이터와 분리했다.

실제 브라우저에서도 리드 초안 캐시 재사용 → 제목·메모 수정 → 저장 → 진행 중 변경 → 새로고침 유지 → 보류 전환을 확인했다([브라우저 기록](../output/product-browser-validation.json)). 검증용 액션에는 추가 검토 필요 메모를 남겼고 실제 실행이나 성과로 기록하지 않았다.

## 다음 액션을 중심으로 한 화면

첫 화면 상단에 추천 진입점을 두고, 실제 agent가 만든 **작업명 → 추천 이유 → 첫 단계 → 산출물 → 검토 후 저장**을 먼저 표시한다. 원문 응답·전체 실행 계획·측정 기준은 펼쳐서 확인한다. 모바일에서도 추천이 주제 목록보다 먼저 나오며 상단에서 주제를 선택할 수 있다. 측정 지표와 연동 절차는 읽기 쉬운 이름과 단계로 표시하고 내부 ID·원문은 보존했다.

실제 보안 초안을 캐시에서 재사용해 추가 모델 호출 0회로 제목·메모 편집, 저장, 액션 관리, 보류 상태 유지까지 확인했다. 390px 화면의 가로 넘침도 없었다. 검증용 액션은 보류이며 실제 실행·성과가 아니다. 이번 변경은 추천의 가시성과 사용 흐름 개선으로, 위의 내용 품질 검토를 통과한 것으로 간주하지 않는다. [검증 기록](../output/next-action-ui-validation.json).

## 품질·비용의 차이

1회 경로는 별도 유료 의미 검토·자동 수정 호출을 하지 않는다. 구조·참조·정책·측정 계약을 코드가 검사하지만, 제품 주장과 산출물의 의미적 적합성은 사용자 검토가 필요하다. 따라서 `propose`는 독립 검토로 승인된 최종안이 아니라 저장 전 검토할 초안이다. 실패를 숨기거나 규칙 요약을 LLM 추천으로 표시하지 않는다.

과제의 평균월 비용은 인프라 $6 + 75질문 × 3채널 × 4.3주 × $0.004 = $9.87이다. 월 $20 한도에서는 이론적으로 M 562회지만 여유가 $0.014뿐이다. 운영 원장은 5회 수집의 보수적 $10.50를 먼저 확보하고 M 500회로 제한한다. 자동 재호출과 외부 분석 API 호출은 없다. [계산 결과](cost-projection.json)의 캐시 50%는 가정이며 운영 달성률이 아니다.

## 아직 하지 않은 것

- 실제 제품 연동 실행, 문서 게시, 후속 수집과 노출 상승 측정.
- 사용자 인증·조직 관리·공개 멀티테넌트 배포. 현재 고객은 서버 설정으로 고정하고 localhost에서 실행한다.
- 유사 경험 검색, 모델 기반 평가 자동화의 운영 연결, Jev 연결, 자동 수집 스케줄러.
- 장기 채택률·인과 효과와 실제 월간 캐시 적중률 측정.

원본 데이터는 과제용 합성 데이터이며 `.example` 페이지의 실제 본문이나 고객 운영 사실로 취급하지 않는다. 사용자 저장·완료·거절은 관측 성과와 구별한다.
