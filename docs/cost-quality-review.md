# 실측 비용과 품질을 함께 보는 절감 검토

2026-10-15 변경 전 검토 기록이다. 구현과 실제 재검증 결과는 [비용 절감 결과](cost-optimization-results.md)를 참고한다.

## 결론

현재 비용으로 월 $100 구독, 분석·추천 1,000회, 마진 80%를 동시에 달성했다고 주장할 수 없다. 최종 내용 검토를 통과한 네 사례의 실제 생성 비용은 평균 **$0.185761875/회**다. 입력·정책 버전·공급사 입력 캐시 상태가 다른 소수의 개발 표본이므로 운영 평균 추정치가 아니라 비용 민감도 계산의 기준이다.

추천하는 순서는 **모델이 생성할 계약 축소 → 근거 중복 제거 → 낮은 추론 설정 실험 → mini 비교**다. 모두 기본 요청당 최대 1회 안에서 수행한다. 마진을 맞추기 위해 추천을 대량 fallback으로 바꾸는 방식은 품질 유지로 인정하지 않는다.

## 과제 계산과 실제 공급사 요금은 별개

[과제 원본](../VIVI_MVP_Sample_Dataset/pricing_assumptions.json)의 `unit_cost_rules`는 모델·티어별 고정 단가와 품질 수치를 바꾸지 못하게 한다. 다른 공급사나 저가 모델도 S/M/L 중 하나로 환산한다. 따라서 토큰 절감과 공급사 모델 변경이 과제의 M $0.018/회를 낮추지는 않는다.

| 계산 | 월 1,000건이 모두 새 생성인 경우 | 80% 달성 조건 |
| --- | --- | --- |
| 과제 M 단가 | $6 + $3.87 + $18 = **$27.87**, 마진 **72.13%** | 유료 호출 ≤562회, 나머지 ≥438건은 유효한 재사용·정당한 0회 판단 |
| 실측 4건 평균 적용 | $6 + $3.87 + $185.761875 = **$195.631875**, 마진 **−95.63%** | 같은 단가라면 유료 호출 ≤54회, 나머지 ≥946건을 비용 없이 처리해야 함 |

수집이 다섯 번인 달에는 고정분이 $10.50이므로 위 상한은 각각 **527회·51회**다. 실제 비용 계산도 수집비·기본 인프라에는 과제 가정을 적용한 혼합 시나리오다. 실제 서비스 전체 원가를 실측했다는 뜻이 아니다. Langfuse가 기존 인프라 배분을 초과하는 고객당 증분을 `h`라고 두면 사용 가능한 모델 예산은 평균월 `10.13 − h`, 다섯 번 수집월 `9.50 − h`다. 기존 $6에 포함된 비용을 다시 더하지 않는다.

최종 4건의 평균 요금을 적용한 월 민감도는 다음과 같다. 다른 요청의 품질은 이 표가 보장하지 않는다.

| 실제 유료 호출 수 | 월 직접 원가 가정 | 마진 | 나머지 요청에 필요한 처리 |
| ---: | ---: | ---: | --- |
| 1,000 | $195.63 | −95.63% | 없음 |
| 500 | $102.75 | −2.75% | 500건 유효한 캐시/정당한 0회 판단 |
| 100 | $28.45 | 71.55% | 900건 유효한 캐시/정당한 0회 판단 |
| 50 | $19.16 | 80.84% | 950건 유효한 캐시/정당한 0회 판단 |

현재 월 500회 원장은 고정 M 단가만 예약·누적한다. 실제 영수증은 보관하지만 실제 청구액으로 입장 예산을 제한하지 않는다. **500회 상한은 실측 마진 80% 보호 장치가 아니다.** 재현 가능한 계산은 [분석 JSON](actual-cost-analysis.json)과 [계산 스크립트](../scripts/analyze_actual_costs.py)에 있다.

## 비용이 생기는 곳

최종 네 사례는 입력 20,873~25,007토큰, 출력 8,483~12,365토큰을 사용했다. 출력은 추론 토큰을 포함한다. 최종 네 건 합계 $0.7430475 중 출력 비용은 $0.613515로 약 **82.57%**다. 추론만 약 49.16%이며 출력 비용에 이미 포함되어 있으므로 다시 더하면 안 된다.

입력 비용을 완전히 없앤 극단적인 가정에서도 출력만 평균 **$0.15337875/회**다. 따라서 입력 압축이나 공급사 프롬프트 캐시만으로 목표를 맞추기 어렵다. 실제 결과 캐시는 모델 호출 자체를 생략하지만, 공급사 프롬프트 캐시는 입력 처리 일부만 할인하고 생성 비용은 남긴다. 공식 문서도 프롬프트 캐시가 동일한 prefix를 재사용하며 적중을 보장하지 않는다고 설명한다. [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

실패를 포함한 개발 10회 총비용은 $1.803157, 단순 호출 평균은 $0.1803157이다. 이 총액을 최종 통과 사례 수 4로 나눈 값은 개발 시도당 성공 산출물 원가를 설명할 수 있어도 정상 운영 호출 단가가 아니다. 실패한 호출을 제거해 운영 성공률을 추정하지도 않는다.

세부 [토큰·문자 구성 감사](token-cost-audit.json)에서는 최종 응답의 **15.29%가 코드로 덮어쓰는 값의 문자 수**였다. 관계 경로·근거 ID·schema enum의 중복을 제거하는 후보는 입력 prompt+schema 문자 수의 약 **14.19%**다. 세부 tokenizer는 설치되지 않아 이 비율은 문자 기준이며 토큰·요금 절감률로 환산하지 않았다. 해당 제거만으로 10배 절감을 주장할 수 없다.

## 우선 검토할 변경

1. **모델이 생성하는 계약을 줄인다.** `summary`, `rejected_alternatives`, `monitoring_plan`, 측정 설명, 자산 선정·게시 체크리스트처럼 코드가 이미 덮어쓰는 값은 모델 응답의 필수 필드에서 제거한다. 모델은 후보 비교·선정 근거·사실에 맞는 초안과 작업만 생성하고, compiler가 기존 화면용 계획을 구성한다. 새 compact schema와 기존 `ProductPlan` 사이의 변환이 필요하며 아직 구현·효과 검증 전이다.
2. **근거를 중복 없이 보낸다.** 선택 질문의 적격 원문·인용·지표를 중심으로 구성하되 모든 자사 자산, 제품 사실·검증 영수증, 기존 작업, 수집 품질, 필요한 주제/과거 비교 근거를 유지한다. 질문 밖의 관측이 실제 판단 근거로 쓰인 사례가 있으므로 무조건 선택 질문만 남기면 안 된다. 관계 edge와 원문 인용에서 재구성되는 중복은 제거 후보이며 전체 canonical pack은 코드 검증용으로 유지한다.
3. **추론 `medium → low`는 별도 실험한다.** 낮은 추론 설정의 비용·품질은 새로 측정한다. 현재 adapter는 medium을 고정한다. 설정을 노출할 때 model·reasoning·출력 한도·schema를 생성 profile과 캐시 식별자, 영수증에 함께 넣어야 한다. GPT-5.4와 mini의 low 지원은 공식 모델 문서에서 확인했다. [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)
4. **mini는 품질 기준을 통과할 때만 선택한다.** 공개 카탈로그에서 structured outputs와 reasoning 지원을 확인했다. 같은 토큰 양을 사용한다는 단순 가격 민감도에서는 mini가 현재 비용의 약 30%지만, 여전히 평균 약 $0.05573/회여서 1,000회 새 생성의 80% 마진은 충족하지 못한다. 실제 출력 길이·추론량·품질이 같다는 뜻은 아니다. nano는 공식 페이지가 deprecated로 표시하고 현재 업무 품질도 확인하지 못했으므로 우선 실험 대상으로 추천하지 않는다. [mini 가격](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [nano 상태](https://developers.openai.com/api/docs/models/gpt-5.4-nano), [OpenRouter 공개 카탈로그 스냅샷](cost-model-catalog.json)

mini를 사용해도 과제 계산에서 판단·초안 작업을 M으로 유지하면 M 단가를 적용한다. S로 바꾸면 과제의 진단/초안 품질 가정이 M 0.81/0.68에서 S 0.58/0.35로 낮아지는 점을 함께 계산해야 한다. 실제 모델 이름만 보고 M과 같은 품질로 단정하지 않는다.

기본 요청 안에서 작은 모델 실패 후 큰 모델로 다시 호출하는 cascade는 만들지 않는다. 모델을 나누더라도 호출 전 결정해야 하고, 작은 모델에서 실패하면 그 요청은 명시적 실패로 기록한다. 이렇게 실패한 요청은 품질 유지 성과에 포함하지 않는다.

단순히 출력 cap을 내리는 방법도 채택하지 않는다. 이전 run1의 두 사례는 10,000토큰 cap에서 잘려 실패했다. 짧게 생성할 계약을 먼저 만들고 실제 사용량·완결성을 확인해야 한다. detailed 근거·선정/배제 이유를 생략해 길이를 맞추는 것은 허용하지 않는다.

## 달성 가능성을 검증할 구체적 목표

[모델별 산술 시나리오](model-cost-scenarios.json)에 같은 토큰 양을 가정한 가격 비교와 아래 목표를 별도로 기록했다. 현재 카탈로그의 mini 표준 가격은 입력/캐시입력/출력 100만 토큰당 **$0.75/$0.075/$4.50**다. [공식 가격](https://developers.openai.com/api/docs/models/gpt-5.4-mini). 공급사 입력 캐시 할인 없이 **입력 6,000 + 추론 포함 출력 3,000토큰**으로 해결한다면 호출당 비용은 **$0.018**이다. 이는 목표 설계의 산술 예시이며 달성한 토큰 수나 품질이 아니다.

- 1,000건 모두 새 생성이면 실제·과제 계산 모두 월 $27.87 / 72.13%로 여전히 실패한다.
- **500건 새 생성 + 500건 유효한 정확 캐시**라면 월 $18.87 / 81.13%, 다섯 번 수집월 $19.50 / 80.50%다. 후자의 추가 인프라 여유는 $0.50뿐이다.
- 1,000건이 전부 새 추천이어야 한다면 공급사 평균 요금 자체가 평균월 $0.01013 이하, 다섯 번 수집월 $0.00950 이하여야 한다. mini 입력이 6,000토큰이면 추론 포함 출력은 각각 약 1,251 / 1,111토큰 이하여야 한다. 현재 핵심 계약의 품질을 이 안에 유지할 수 있다는 증거는 없다. 더구나 과제 M 고정 단가 때문에 실제 요금 목표를 달성해도 과제 마진은 별도 문제다.

따라서 **compact + 낮은 추론 + mini의 실제 요금 검증**과 **유효한 결과 재사용률 측정**이 함께 필요하다. 50% 적중률을 가정만으로 채우거나 1,000건 중 목록 조회·상태 변경을 섞으면 안 된다. 고객·근거 버전·제품 맥락·현재 액션·생성 profile이 같은 경우만 재사용하고, 현재 액션 중복과 의미적 유효성을 다시 검사한다.

## 품질과 운영 예산의 검증 기준

기존 lead·unsupported·security·confirmed를 각 변경 단계에서 독립 요청으로 검증한다. 요청마다 모델 최대 1회, SDK 재시도 0, 자동 critic·repair 0이다. 네 사례 점수가 기존 9/9/10/9보다 낮아지지 않고, 각 축 1점 이상·P1/P2 없음·필수 회귀 전부 충족을 초기 통과 조건으로 둔다. 사례 하나라도 실패하면 그 변경을 기본값에 채택하지 않는다. 한 번의 4건 통과는 장기 품질 보장이 아니므로 유망한 설정만 반복 표본과 새로운 질문에서 확인한다.

유지해야 할 계약은 같은 문제의 서로 다른 후보 3개, 선정/배제/변경 조건, 근거 참조, 모든 자사 자산 역할과 ALL 재사용 기준, 미지원 사실, 실제 연동 경로·receipt와 6단계 검사, 실행 초안·작업·완료 기준이다. 주요 성과는 언급·추천, 인용은 보조다. 게시 URL AND owned source ID AND 게시 시각, 미확정 주장 해소, D7/14·결측≠0 규칙도 유지한다.

운영에는 과제 환산 원장 외에 실제 비용 원장이 필요하다. 호출 전 선택 profile의 입력·출력 상한과 uncached 가격으로 비용을 보수적으로 예약하고, 응답 뒤 공급사 비용으로 정산한다. 실패·미확인 비용도 예약을 유지하며 동시 호출은 원자적으로 제한한다. 이 장치는 과금 폭주를 제한할 뿐, 예산 소진 후 충분한 추천 품질을 제공한다는 보장은 아니다.

현재 산출물은 비용 구조·절감 후보·수용 기준에 대한 검토다. 새 모델이나 축소 계약의 품질 보존을 확인한 결과로 해석하지 않는다.
