# 에이전트 실행 검증

> 이 문서는 v6 실행의 역사적 기록이다. 이후 측정 범위·연동 절차 수정과 재검증은 [최신 수정 보고서](failure-fixes.md)에 기록한다.

2026-10-14 기준. LangGraph 에이전트가 과제의 원본 데이터를 읽고 OpenAI API로 진단·액션 작성·검토를 수행했다. 데이터는 과제용 합성 데이터이며 실제 고객 운영 데이터가 아니다. 웹 화면과 API 서버는 아직 구현하지 않았다. 커밋은 하지 않았다.

## 검증 범위

- Python 3.12, LangGraph, Pydantic 구조화 출력, SQLite 체크포인트·호출 원장.
- 최종 모델 `gpt-5.4-2026-03-05`, 모든 단계 `reasoning.effort=medium`.
- 정상 분석 3회, 수정·재검토를 포함해 최대 5회. SDK 자동 재시도 없음.
- 서로 다른 4개 주제, 제품 기능 미지원·지원 확인의 2개 맥락, 추상적 액션·존재하지 않는 근거의 2개 반례: 총 8개 사례.
- 기대 조건은 생성 프롬프트에 전달하지 않는다. 생성과 별도 호출로 평가하지만 같은 모델을 사용하므로 오류가 상관될 수 있다. 일부 사례는 코드 검사다.
- 코드 테스트 **109개 및 하위 테스트 13개 통과**. 단위·통합 테스트는 재개, 캐시, 예산, 참조·소유권, 제품 확인 기록, 결정 정책, 검토 실패 차단을 포함한다.

## 발견한 오류와 수정

초기 출력은 그럴듯한 초안을 만들었지만, 자동 검토가 통과시킨 결과에서도 잘못된 수치와 미확인 기능 주장이 발견됐다. 한 번의 높은 검토 점수만으로 추천 품질을 인정하지 않았다.

| 발견한 문제 | 적용한 수정 |
| --- | --- |
| 언급·추천·자사 인용 비율을 같은 수치로 서술 | 지표는 코드로 계산하고 진단의 정량 사실도 분자·분모에서 렌더링 |
| 근거 ID에 설명을 붙이거나 편집할 수 없는 출처 선택 | 근거·지표·질문·자사 편집 출처를 동적 스키마의 허용 목록으로 제한하고 코드로 재검사 |
| 수집률 9/15에서도 콘텐츠 처방, 이미 추천 15/15인 주제에 불필요한 개선 | 수집률 80% 미만은 `needs_data`, 그 외 추천 100%는 `observe`로 제한하는 초기 제품 정책 |
| 기능 확인 기록이 있는데도 조회 불가 또는 미확인으로 처리 | 제품 확인 기록을 근거 인덱스에 포함하고 맥락을 캐시 키에 반영 |
| 검토자가 부정문을 기능 지원 주장으로 잘못 판정 | 후보의 실제 주장과 검증 기록을 대조하도록 검토 지침 수정, 명시적 추론 설정 |
| 액션 여러 개에서 초안 누락·측정 일정 불일치 | 우선순위 액션 1개, 약속한 초안 수량과 게시 1·2주 후 각 1회 측정 지침 |

정량 사실의 코드 렌더링이 자유 서술 전체의 정확성을 보장하지는 않는다. 액션 초안의 제품 주장과 원인 가설은 여전히 의미 검토와 담당자 확인이 필요하다.

실패한 실행도 보존했다. 아래 수치는 서로 다른 구현·프롬프트·추론 설정의 회귀 실행이므로 모델 간 공정한 성능 비교가 아니다.

| 실행 기록 | 기대 조건 충족 |
| --- | --- |
| [초기 GPT-4.1](../output/evaluation.gpt-4.1.json) | 1/8 |
| [초기 GPT-5.4](../output/evaluation.gpt-5.4.json) | 3/8 |
| [검토 추론 설정 후](../output/evaluation.reasoned.json) | 5/8 |
| [정량 사실·수집 정책 반영 중간 실행](../output/evaluation.final.json) | 4/8 |
| [액션 수·판단 정책 제한 중간 실행](../output/evaluation.release.json) | 5/8 |

`final`·`release`는 개발 중 붙인 파일명이다. 최종 제출 상태는 아래 `shipped` 실행으로 식별한다. 중간 실행을 통과 결과로 바꾸거나 숨기지 않았다.

## 최종 평가

**8개 중 6개 통과. 초기 목표인 7/8에는 미달했다.** [최종 실행 JSON](../output/evaluation.shipped.json)의 suite ID는 `0bce407176721b4b6d845226cd149b4164eefd374b08c3b7fd181b0cd04640ce`다. 실행 오류 없이 8개를 모두 평가했다.

| 사례 | 결과 | 실제 판단과 확인 사항 |
| --- | --- | --- |
| 리드 관리 실행 브리프 | 통과 | `recommend`; Q068 0/3에 대응하는 검증표·가이드·FAQ·완료 조건 |
| 자동화가 이미 추천 15/15 | 통과 | `observe`; 불필요한 개선 액션을 만들지 않고 재검토 조건 제시 |
| 규모 확장 수집 누락 | 통과 | `needs_data`; 유효 9/15, 빠진 질문·채널 재수집 |
| 보안 기존 자산 | 통과 | `recommend`; 언급 0/12와 문서 인용 6/12 구별, 기존 문서 확인 후 개정·신설 |
| 기능 미지원 확인 | 실패 | 미지원 사실은 지켰으나 질문·주제 지표를 혼용해 수정 후에도 `review_required` |
| 추상적인 액션 거절 | 통과 | 유효 근거 ID만으로 승인하지 않고 구체성·문제 연결·측정 부족 지적 |
| 존재하지 않는 근거 거절 | 통과 | 코드 검사에서 차단; 모델 호출 없음 |
| 기능 지원 확인 | 실패 | `recommend`와 맥락별 캐시는 정상이나 연동 절차가 일반적이고 확인된 경로명에도 확인 대기 표시가 남음 |

최종 결과의 자동 검토·평가가 기록한 필수 위반과 금지 주장은 0건이다. 이는 독립적인 무오류 보증이 아니다. 아래 별도 대조에서는 측정 범위와 운영 약속의 조건 표현을 보완할 필요를 확인했다.

분석 6건의 생성·수정·검토에 24회, 별도 평가·반례 검토에 8회로 총 **32회** 실제 API 호출을 사용했다. 과제의 M 단가를 적용한 환산액은 **$0.576**이며 실제 공급사 청구액은 미측정이다. lead·automation·미지원 기능 사례는 각각 5회, scale·security·지원 확인 사례는 각각 3회로 분석당 한도를 지켰다.

현재 판단은 **제공 데이터에서 유용한 조건부 액션을 만드는 프로토타입은 구현했지만, 모든 맥락에서 충분히 구체적인 실행안을 안정적으로 내는 품질 목표는 아직 충족하지 못했다**는 것이다. 다음 보완 대상은 질문별 주요 지표와 주제 전체 보조 지표의 측정 범위를 구조화하고, 검증된 연동 사실과 미제공 설정 상세를 구별해 초안을 작성하는 계약이다.

### 대표 액션의 별도 대조

[최종 리드 관리 브리프](../output/lead-action.md)는 `completed / recommend`, 준비 상태는 `needs_input`이다. 제품 PM이 기능 지원 범위와 기존 문서 본문을 확인하고, 콘텐츠 담당자가 질문 Q068에 답하는 가이드 1건을 개정하거나 신설하는 작업이다. 검증표·가상 필드 매핑·FAQ 3문 3답·작업 순서·승인 조건을 포함한다.

생성·평가 호출과 별도의 검토 에이전트가 최종 plan을 근거 파일과 대조했다. Q068 0/3, Perplexity 0/5, 비교 가능한 자사 인용 7/15→2/15, 자산 SRC003·SRC022·SRC001의 자사 소유를 확인했다. 미확인 제품 기능의 사실 단정은 발견하지 못했다. FAQ 수량과 게시 1·2주 후 각 1회 일정도 일치했다. 이 검토도 사람의 실제 제품 검증을 대신하지 않는다.

**남은 보완:** 주된 측정은 Q068의 3채널로 명확하지만, 보조 지표인 Perplexity 전체 비율은 Q066~Q070 5질문이 분모다. 최종 초안은 해당 5질문의 동시 재수집을 명시하지 않았다. 실행 담당자는 보조 지표를 유지하면 같은 두 시점에 Q066~Q070도 수집하도록 측정 범위를 확정해야 한다. 원본 출력은 이 발견을 숨기기 위해 수정하지 않았다.

보안 사례도 별도로 대조했다. 자사 언급 0/12와 문서 인용 6/12를 구별했고, 기존 SRC021의 본문 확인 후 개정·신설을 선택하는 검증표·랜딩 초안·FAQ 4문 4답을 제시했다. 인증·보안 기능 날조는 발견하지 못했지만, “정보를 남겨주시면 담당 경로를 안내합니다”라는 운영 약속도 확인 후 게시할 조건부 문구임을 더 명확히 할 필요가 있다. 따라서 자동 평가 통과를 모든 문장의 정확성 보증으로 해석하지 않는다.

## 재현

```sh
uv sync --frozen
uv run pytest -q
uv run vivi-agent analyze lead --output output/lead.json
uv run vivi-agent evaluate --output output/evaluation.json
docker compose build agent
docker compose run --rm agent analyze lead --output /app/output/lead.json
```

루트 `.env`의 키를 사용한다. 키는 Git과 Docker 이미지에 포함하지 않는다. 결과 재사용 키에는 데이터·주제·시점·모델·제품 맥락·프롬프트·구현 버전이 포함된다. 동일 상태로 재실행하면 추가 모델 호출 없이 결과를 읽는다.

최종 소스의 Docker 빌드와 호스트 상태 저장소를 마운트한 재실행을 확인했다. `automation`은 `observe`, `lead`는 `recommend`이며 모두 `cache_hit=true`, 동일 분석 키의 호출 수는 각각 5회로 유지됐다([automation 기록](../output/automation.shipped.docker.json), [lead 기록](../output/lead.shipped.docker.json)). 이미지 내부에 `/app/.env`가 없음을 확인했다. 앞선 버전에서는 기본 named volume만 사용해 컨테이너 내부의 실제 3회 호출과 새 컨테이너에서 추가 호출 없는 재사용도 확인했다([첫 실행](../output/automation.docker.json), [재실행](../output/automation.docker-restarted.json)).

## 사용량과 비용 구분

[개발 전체 사용량](../output/runtime-usage.json)은 호스트 원장 기준 완료 179회, 진행 중·실패 0회다. 초기 모델 비교와 모든 프롬프트 수정·평가를 포함하며 고객 한 명의 운영 비용이 아니다. 입력 2,803,415토큰, 출력 431,082토큰을 응답 영수증에서 집계했다. 캐시 입력과 추론 출력은 각각 해당 합계의 부분집합이다. 별도 Docker 원장의 실제 3회 호출은 이 집계에서 제외했다.

179회의 과제 단가 환산은 $3.222이고, 그 안에 최종 평가 32회의 $0.576이 포함된다. 실제 공급사 청구액은 미측정이다. [월 비용 시나리오](cost-projection.json)는 별개의 가정 계산이다. 15주제·월 5개 스냅샷·묶음당 최대 5회·고정 맥락/버전의 조건에서는 고객당 월 $17.25, 마진 82.75%로 계산된다. 월 500회 상한을 모두 쓰면 고정비 포함 $19.50이다. 1,000개 요청을 실제 재생해 처리량이나 캐시 적중률을 입증한 것은 아니다.

## 해석의 한계

8개 사례는 개발 중 반복 사용한 회귀 평가이며 미공개 검증 세트가 아니다. 통과율을 일반적인 정확도나 고객 채택률로 해석하지 않는다. 후속 수집을 실행해 가시성 개선이나 인과 효과를 입증한 상태도 아니다.

실제 문서 본문과 제품 사양은 제공되지 않았고 `.example` URL을 크롤링하지 않았다. 기능 확인 사례의 지원 여부·연동 경로는 평가용 가상 맥락이다. 실제 추천에서 본문 확인과 기능 검증이 선행 조건이면 게시 전에 담당자가 확인해야 한다.

Jev는 원자적 판단을 보조하는 선택적 경계만 [설계](jev-integration.md)에 반영했다. Jev API 호출과 한국어 판단 성능 검증은 수행하지 않았다. 단일 고객 CLI 범위이며 인증·권한·수집 스케줄러·액션 실행 상태 UI는 후속 구현이다.
