# VIVI Product Engineer — 지원자용 합성 데이터셋 (v2)

이 데이터는 **가상의 SaaS 브랜드와 AI 검색 결과를 기반으로 만든 채용 평가용 데이터**입니다. 실제 ChatGPT, Gemini, Perplexity 답변이나 외부 기업의 실측 결과가 아닙니다. 모든 `.example` 도메인은 접속할 수 있는 실제 웹사이트가 아니라 예시 주소입니다.

## 시나리오
여러분은 CRM 솔루션 **OrbitCRM(`BR001`)**의 마케팅 담당자를 돕는 제품을 만듭니다. 경쟁사는 NovaDesk, LeadFlow, ClientNest, PicoSales입니다. 고객이 AI 검색에 던질 법한 질문 75개를 정해 두고, 세 AI 채널에서 두 번 답변을 수집했습니다.

## 데이터 규모
- 브랜드 5개 (분석 대상 `OrbitCRM`, `BR001`)
- 질문 75개 / 주제 15개 (주제당 5개)
- AI 응답 관측 456건 (질문 75 × 채널 3 × 수집일 2 = 450건 기준, 재수집분 포함)
- 브랜드 언급 976건 / 인용 연결 1,118건 / 출처 49개
- 수집일: 2026-09-15, 2026-10-06 (가상 기록)

## 파일
| 파일 | 내용 | 연결 키 |
|---|---|---|
| brands | 브랜드 정보와 분석 대상 구분 | brand_id |
| questions | 검색 질문, 의도, 주제, 중요도, 관심도 | question_id |
| observations | 채널별 AI 답변과 수집 상태 | observation_id, question_id |
| mentions | AI 답변에 등장한 브랜드(등장 순서, 맥락, 감성) | observation_id, brand_id |
| sources | 인용 출처의 메타데이터 | source_id, brand_id |
| citations | 답변과 인용 출처의 연결 | observation_id, source_id |
| pricing_assumptions.json | 비교 가능한 원가 계산을 위한 가상 단가·매출 조건 | cost_id |
| manifest.json | 테이블별 레코드 수, 키 관계, 열거형 값 | - |
| sample_observation.json | 질문 1개와 그 관측 3건 예시 | - |

테이블마다 **JSON과 UTF-8 BOM CSV**를 모두 제공하니 편한 형식을 쓰면 됩니다. CSV에서 불리언은 `true`/`false`, 빈 값은 빈 칸(null)입니다.

## 주요 컬럼
- `questions.search_intent`: `informational`(정보 탐색) · `commercial`(비교·추천) · `transactional`(체험·견적·구매 행동)
- `questions.importance_score`(0~100), `estimated_monthly_interest`(월 관심도): **가상 지표**이며 실제 시장 수요가 아닙니다.
- `observations.collection_status`: `complete` · `partial` · `failed`
- `observations.quality_flag`: 수집 단계에서 붙인 품질 표시. 값이 비어 있다고 품질 문제가 없다는 뜻은 아닙니다.
- `observations.target_mentioned`, `mention_count`, `citation_count`: 탐색 편의용 **요약 값**입니다. 원본은 `mentions`와 `citations` 테이블이니 함께 확인하세요.
- `mentions.mention_rank`: 답변 안에서 브랜드가 처음 등장한 순서(1부터)
- `mentions.mention_context`: `recommended`(근거와 함께 추천) · `listed`(이름만 나열)
- `mentions.sentiment`: `positive` · `neutral` · `negative`
- `sources.is_brand_owned`, `sources.brand_id`: 출처가 어느 브랜드 소유인지 나타냅니다.
- `citations.citation_context`: `brand_official` · `comparison_table` · `user_review` · `supporting_reference`

## 데이터를 쓸 때 주의할 점
- 데이터 품질 문제를 **의도적으로** 넣었습니다. 수집 실패, 부분 수집, 재수집, 메타데이터 누락, 요약 값 불일치 등이 있습니다. 무엇을 어떻게 찾아서 처리할지는 지정하지 않습니다. 처리했다면 방법과 그것이 결과에 준 영향을 README에 적어 주세요.
- 비슷한 의미의 질문이 일부 있고, 같은 질문이라도 채널과 수집일에 따라 답변이 다릅니다.
- **모든 데이터가 개선 액션을 필요로 하는 것은 아닙니다.** 무엇을 먼저 개선할지는 지원자가 판단합니다.
- 액션 생성·상태 변경 데이터는 제공하지 않습니다. 저장 구조는 지원자가 설계하고 구현합니다.

## 비용 모델
`pricing_assumptions.json`에 평가자 간 비교를 위한 가상 단가와 모델 티어별 성능이 들어 있습니다. 과제 안내문에 정한 대로 월 구독료 **$100**, 고객당 월 요청 **1,000회**, 초기 고객 **100개사**, 목표 매출총이익률 **80% 이상**(고객당 월 원가 $20 이하)을 기준으로 합니다.

**요청 1회**는 고객이 분석·추천 기능을 한 번 실행하는 것입니다(예: 주제 분석 요청, 액션 추천 생성). 목록 조회나 액션 상태 변경은 요청에 넣지 않습니다. 기준 구조에서는 요청 1회마다 `AI-M` 모델 호출 1회와 외부 분석 API 호출 1회가 일어난다고 가정합니다. AI 답변 수집은 요청과 별개로 시스템이 주기적으로 돌리는 작업이며, 기준 주기는 **주 1회**입니다.

### 단가표

| cost_id | 항목 | 단가 |
|---|---|---:|
| `AI-S` | 모델 호출 — Small 티어 | $0.003 / 호출 |
| `AI-M` | 모델 호출 — Medium 티어 (기준) | $0.018 / 호출 |
| `AI-L` | 모델 호출 — Large 티어 | $0.060 / 호출 |
| `COL001` | AI 답변 수집 (질문 1개 × 채널 1개) | $0.004 / 수집 |
| `API001` | 그 밖의 외부 유료 API 호출 | $0.012 / 호출 |
| `INF001` | 호스팅·DB·저장 | $6 / 고객·월 |

### 티어별 성능 (가상)

| 작업 | 예시 | 지표 | S | M | L |
|---|---|---|---:|---:|---:|
| 응답 분류 | 언급·감성·인용 맥락 판별 | 정확도 | 94% | 97% | 98% |
| 원인 진단 | 특정 주제·채널에서 자사가 안 보이는 이유 판단 | 정확도 | 58% | 81% | 92% |
| 액션 초안 생성 | 개선 액션 제목·근거·실행 단계 작성 | 담당자 채택률 | 35% | 68% | 83% |

실제 모델을 호출하지 않아도 이 수치로 품질 영향을 계산할 수 있습니다. 위 세 작업에 없는 모델 작업을 쓴다면 가장 가까운 작업의 수치를 쓰고 그 판단을 적어 주세요.

### 수집 주기 (가상)

고객당 질문 75개 × 채널 3개 = 회당 225건을 수집합니다. 주기가 짧을수록 변화를 빨리 알지만 원가가 늘어납니다. 품질 지표는 **평균 변화 감지 지연 ≈ 수집 주기 ÷ 2**로 봅니다.

| 주기 | 월 수집 건수 | 고객당 월 원가 | 평균 감지 지연 |
|---|---:|---:|---:|
| 월 1회 | 225 | $0.90 | 약 15일 |
| 격주 | 450 | $1.80 | 약 7일 |
| 주 1회 (기준) | 968 | $3.87 | 약 3.5일 |
| 매일 | 6,750 | $27.00 | 약 0.5일 |

질문마다 주기를 다르게 정해도 됩니다. 주기 설계는 선택 사항이며, 기준 주기(주 1회)를 그대로 써도 됩니다. 제공 데이터셋은 수집이 2회뿐이므로, 주기의 영향은 위 지표로 계산해 주세요.

### 단가와 성능 수치는 바꿀 수 없습니다
위 단가와 성능 수치는 **고정**입니다. 다른 LLM, 저가 모델, 무료 티어, 자체 호스팅 등 어떤 서비스를 쓰더라도 아래 규칙으로 환산합니다. 지원자 간 비교를 같은 기준으로 하기 위해서입니다.

- 모델 추론 호출(LLM·임베딩 등) 1회 = 선택한 티어(`AI-S`·`AI-M`·`AI-L`) 1회
- AI 답변 수집 1회(질문 1개 × 채널 1개) = `COL001`
- 그 밖의 외부 유료 API 호출(검색·분석 등) 1회 = `API001`
- 호스팅·DB·저장 = `INF001`에 포함
- 요청 1회에 호출이 여러 번이면 호출 수만큼 셉니다.

원가를 줄이는 방법은 세 가지입니다. **호출 횟수와 구조**를 바꾸는 것(캐시, 사전 계산, 규칙 기반 대체, 호출 생략 등), **작업마다 티어를 고르는 것**, **수집 주기를 설계하는 것**입니다. 티어 선택과 주기 설계는 필수가 아닙니다. 바꿨다면 성능표와 감지 지연을 근거로 원가와 함께 품질 영향을 계산해 README에 적어 주세요.
