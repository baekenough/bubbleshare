제공 데이터와 실제 API로 생성한 작업 초안이다. 제품 연동 실행이나 게시·후속 수집을 완료했다는 뜻이 아니다.

## Q069 의도에 맞춘 ‘리드→영업기회 전환’ 가이드로 SRC022 우선 개정 여부를 확인하고, 부족하면 새 자사 가이드를 발행

Q069는 전환율 개선이라는 정보형 과업인데, 현재 OrbitCRM은 이 질문에서 자사 인용이 0/3입니다. 같은 주제 내에서 Q070은 2/3 노출이므로 브랜드 전체 인지도보다 과업-자산 정렬 문제가 우선으로 보입니다.

담당 역할 제안: 콘텐츠 마케팅 매니저 · 준비 상태: `needs_input`

### 선행 조건

- SRC022 본문 열람 권한이 필요합니다.
- OrbitCRM 관련 예시 문구를 확인할 제품 담당자 검수가 필요합니다.
- 새 문서 생성 시 게시 권한과 발행 후 source ID 등록 절차가 필요합니다.

### 자산 선택

도입문:
리드가 충분한데도 영업 기회로 잘 넘어가지 않는다면, 더 많은 유입보다 현재 리드가 어느 단계에서 멈추는지부터 확인해야 합니다. 특히 점수 기준, 우선 연락 순서, 영업기회 전환 기준이 분리돼 있으면 전환율이 흔들리기 쉽습니다.

핵심 답변 박스:
리드→영업기회 전환율을 높이려면 ①유입 경로별 리드를 구분하고 ②점수 기준을 한 번 정리한 뒤 ③상위 점수 리드의 첫 응답 시간을 줄이고 ④영업기회 전환 기준을 명확히 하며 ⑤주간 점검표로 병목 단계를 반복 확인해야 합니다.

섹션 1. 유입 경로를 섞어 보지 말기
- 웹, 광고, 추천, 재방문 문의를 한 묶음으로 보면 병목이 가려집니다.
- 먼저 리드를 유입 경로별로 나눠 어디서 전환이 멈추는지 봅니다.

섹션 2. 점수 기준을 먼저 합의하기
- 점수는 ‘누가 먼저 연락할지’를 정하기 위한 기준이어야 합니다.
- 예시 기준: 회사 규모, 문의 목적, 도입 시기, 예산 확정 여부.
- OrbitCRM 적용 예시: [제품 확인 후 입력]

섹션 3. 상위 리드의 첫 응답 시간을 줄이기
- 점수가 높은 리드부터 연락 순서를 정하지 않으면 좋은 리드가 뒤로 밀립니다.
- 팀 내 SLA 예시: 상위 점수 리드는 영업일 기준 [제품 확인 후 입력] 안에 1차 연락.

섹션 4. ‘영업기회’의 정의를 문서로 남기기
- 단순 문의와 실제 기회를 구분하는 기준이 없으면 전환율이 팀마다 다르게 계산됩니다.
- 예시 기준: 담당자 확인, 도입 시기 확인, 예산 범위 확인.

섹션 5. 주간 점검표로 병목 한 곳만 먼저 고치기
- 한 번에 모든 단계를 바꾸기보다, 이번 주에는 ‘첫 응답 지연’ 같은 병목 1개만 수정합니다.
