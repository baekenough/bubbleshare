# Q068(“웹사이트 문의를 CRM 리드로 자동 등록하는 방법은?”)에서 OrbitCRM은 0/3으로 완전 무노출이지만, 웹 문의의 CRM 리드 자동 등록 지원은 평가용 공식 연동 경로 A에서 확인되었습니다. 따라서 전사 홍보보다 이 과업을 직접 설명하는 자사 자산을 정비하고, 같은 경로로 검증 기록을 남기는 1건이 가장 가치가 큽니다.

상태: `completed` · 결정: `recommend` · 모델: `openai/gpt-5.4`

제공 데이터와 실제 API로 생성한 작업 초안이다. 제품 연동 실행이나 게시·후속 수집을 완료했다는 뜻이 아니다.

## Q068용 ‘웹 문의→CRM 리드 자동 등록’ 자사 가이드 정비 및 검증 기록화

구현형 질문인 Q068에서 OrbitCRM 관련 언급·추천·자사 인용이 모두 0/3이므로, 검증된 경로를 정확히 설명하는 자사 가이드가 있거나 새로 생기면 모델이 답변에 OrbitCRM을 연결할 여지가 커집니다.

담당 역할 제안: 콘텐츠 마케팅 리드(세일즈옵스/운영 협업) · 준비 상태: `needs_input`

### 선행 조건

- SRC001·SRC003·SRC021·SRC022 본문 확인 권한 확보
- 평가용 공식 연동 경로 A를 실제로 조작할 운영 담당자 지정
- 문의 폼 입력 예시와 CRM 리드 확인 권한 확보
- 선택 자산의 편집 또는 신규 문서 발행 권한 확보

### 자산 선택

본문에 ‘웹사이트 문의→CRM 리드 자동 등록’ 과업을 직접 설명할 수 있는 자산만 최종 게시 자산으로 선택합니다. SRC001·SRC003·SRC022 중 하나의 본문이 이 과업을 직접 다루고 평가용 공식 연동 경로 A 및 ‘네이티브 기능 지원을 추론하지 않음’ 문구를 무리 없이 수용하면 해당 자산을 개정하고, 세 자산 모두 직접 과업 답변이 부족하면 새 가이드를 생성합니다. SRC021은 주 자산이 아니라 개인정보/보안 주의 링크 후보로만 점검합니다.

- `SRC001` · 재사용 후보: 제품 기능 페이지 본문에 웹 문의 수집, 리드 생성, 자동화/연동 개요가 직접 있으면 Q068의 주 자산으로 개정 후보입니다. 그런 직접 과업 섹션이 없으면 새 가이드 생성으로 전환합니다.
- `SRC002` · 이번 작업에서 제외: 요금 안내 자산은 구현형 ‘방법’ 질문의 직접 답변 자산이 아니며, 무료 체험 여부도 unknown이어서 본 작업의 핵심 근거로 쓰기 어렵습니다.
- `SRC003` · 재사용 후보: 일반 CRM 활용 가이드 본문에 문의 접수→리드 등록 흐름이나 운영 절차가 있으면 Q068의 주 자산으로 개정 후보입니다. 해당 흐름이 없으면 새 가이드 생성으로 전환합니다.
- `SRC004` · 이번 작업에서 제외: 고객 사례 자산은 사례 증빙에는 쓸 수 있어도 ‘자동 등록하는 방법’ 자체를 직접 설명하는 주 자산으로는 적합도가 낮습니다.
- `SRC021` · 재사용 후보: 보안·개인정보 보호 정책 본문에 웹 문의 데이터 처리 주의사항이 있으면 최종 가이드의 보조 링크 후보로 재사용을 점검합니다. 다만 직접 과업 답변이 아니면 주 자산으로는 선택하지 않습니다.
- `SRC022` · 재사용 후보: 리드 스코어링 가이드 본문에 문의 유입 이후 리드 생성·분류 흐름이 있으면 Q068의 주 자산으로 개정 후보입니다. 스코어링만 다루면 새 가이드 생성으로 전환합니다.

### Q068 대응 자사 가이드 초안

제목: 웹사이트 문의를 CRM 리드로 자동 등록하는 방법: OrbitCRM 검증 가이드

핵심 답변
OrbitCRM에서 웹 문의를 CRM 리드로 자동 등록하는 지원은 평가용 공식 연동 경로 A에서 확인되었습니다. 단, 이 확인만으로 네이티브 기능 지원을 의미하지 않습니다.

사전 확인 항목
- 문의 수집 위치: [운영 담당자 확인 후 입력]
- 리드로 보낼 입력 항목: [운영 담당자 확인 후 입력]
- 필수 입력 항목: [운영 담당자 확인 후 입력]
- 중복 처리 정책: [운영 담당자 확인 후 입력]
- 권한/승인 절차: [운영 담당자 확인 후 입력]

실행 절차
1. 테스트용 가상 문의 1건을 준비합니다.
2. 평가용 공식 연동 경로 A를 통해 문의 항목과 CRM 리드 항목을 대응시킵니다.
3. 1회 제출 후 생성된 리드 값이 입력값과 일치하는지 비교합니다.
4. 동일 인물 재제출과 필수 항목 누락 1건을 별도로 시험해 운영 정책과 결과를 기록합니다.

확인 질문 3개
- 이 경로가 네이티브 기능인가요? → 확인된 사실은 평가용 공식 연동 경로 A 지원뿐입니다.
- 어떤 필드가 꼭 필요하나요? → [운영 담당자 확인 후 입력]
- 중복 문의는 어떻게 처리되나요? → [운영 담당자 확인 후 입력]

### 게시 결정 체크리스트

- 최종 자산은 ‘웹사이트 문의→CRM 리드 자동 등록’을 직접 설명하는가?
- ‘평가용 공식 연동 경로 A’ 문구가 정확히 들어갔는가?
- ‘이 확인만으로 네이티브 기능 지원을 의미하지 않습니다’ 문구가 들어갔는가?
- 필수값/중복 정책/권한은 확인값만 적고, 미확인 값은 [제품 확인 후 입력]으로 남겼는가?
- 게시 URL 또는 신규 소스 등록 정보가 측정 대상에 연결되었는가?

### 검증된 연동 경로와 실행 절차

확인된 경로: **평가용 공식 연동 경로 A**

확인 기록: `eval-product-check-001`

추가로 확인할 설정:

- 실제 UI/API 위치
- 필요 권한과 역할
- 문의 원본 폼 종류와 접근 방식
- CRM 목적지 객체/필드 식별자
- 중복 제출 처리 정책
- 필수 입력 항목 규칙
- 체험/시험 환경 사용 가능 조건

#### 1. input

입력: 허구의 문의 예시: 이름 김가상, 회사 샘플테크, 이메일 test-lead@example.com, 전화 010-0000-0000, 문의 내용 '데모 요청', 유입 페이지 '/demo-request'

작업: 평가용 공식 연동 경로 A로 시험할 원본 입력값 1건을 확정하고 문서로 고정합니다.

기대 결과: 이후 단계에서 비교할 단일 입력 원본이 확정됩니다.

남길 증빙: 원본 입력 문서 또는 캡처, 작성 시각 기록

#### 2. field_mapping

입력: 앞 단계의 확정 입력값과 운영 담당자가 확인한 문의 폼 항목/CRM 리드 항목 목록

작업: 평가용 공식 연동 경로 A를 사용해 문의 입력값이 어느 CRM 리드 항목으로 들어가는지 운영 확인 기준으로 매핑표를 작성합니다.

기대 결과: 운영 담당자가 확인한 항목 대응표가 완성되고, 미확인 항목은 빈칸이나 보류로 남깁니다.

남길 증빙: 필드 매핑표, 운영 담당자 확인 메모

#### 3. normal_submission

입력: 필수값이 모두 포함된 허구의 문의 1건

작업: 평가용 공식 연동 경로 A를 통해 문의를 1회 제출하고 생성된 리드 레코드를 확인합니다.

기대 결과: 운영자가 사전에 확인한 정상 제출 정책 범위에서 결과가 생성되며, 확인 가능한 필드 값이 원본 입력과 일치합니다.

남길 증빙: 제출 시각 기록, 생성된 레코드 캡처 또는 운영자 노트

#### 4. duplicate_submission

입력: 이름/이메일 등 동일 식별값을 가진 같은 허구의 문의를 다시 1회 제출

작업: 평가용 공식 연동 경로 A를 통해 동일 식별값 문의를 재제출하고 실제 결과를 운영자가 확인한 중복 정책과 비교합니다.

기대 결과: 실제 결과가 운영자가 사전에 확인한 중복 정책과 일치하는지 판정할 수 있습니다.

남길 증빙: 1차/2차 제출 기록, 결과 비교 캡처 또는 운영자 메모

#### 5. missing_required_field

입력: 운영자가 필수라고 확인한 항목 1개를 비운 허구의 문의

작업: 평가용 공식 연동 경로 A를 통해 필수 항목 누락 상태로 제출해 실제 결과를 운영자가 확인한 필수값 규칙과 비교합니다.

기대 결과: 실제 결과가 운영자가 사전에 확인한 필수값 규칙과 일치하는지 판정할 수 있습니다.

남길 증빙: 오류 화면 캡처 또는 생성 결과 기록, 운영자 메모

#### 6. reconcile

입력: 정상 제출/중복 제출/누락 제출 결과와 CRM에서 확인한 레코드 정보

작업: 각 제출 시각과 식별 정보를 CRM 레코드 식별 정보와 대조하고, 원본 입력값과 생성값 비교표를 마감합니다.

기대 결과: 제출별 결과와 CRM 레코드가 연결되고, 일치/불일치가 항목별로 정리됩니다.

남길 증빙: 대조표, 레코드 식별 정보 캡처 또는 운영자 노트

공개 전 통과 조건:

- 외부 공개 문구에 평가용 공식 연동 경로 A가 정확히 기재되었다.
- 외부 공개 문구가 검증 사실만 말하고 네이티브 기능 지원으로 확대 해석하지 않는다.
- 미확인 운영값은 [제품 확인 후 입력]으로 남겨 허위 기재가 없다.
- 게시 URL 또는 신규 소스 등록 정보가 측정 대상으로 연결되었다.

### 작업 순서

1. SRC001·SRC003·SRC021·SRC022 본문을 selection_rule로 점검해, 직접 과업 답변이 가능한 1개 자산을 개정 대상으로 고르거나 새 가이드 생성으로 결정합니다. 결과: 자산별 점검 메모와 최종 분기(기존 자산 개정/새 가이드 생성) 1건
2. 선택된 분기에 맞춰 Q068 대응 가이드 초안을 작성하되, 평가용 공식 연동 경로 A와 비네이티브 주의 문구를 정확히 넣고, 미확인 운영값은 [제품 확인 후 입력]으로 남깁니다. 결과: 게시 가능 초안 1부와 표현 검수 완료본
3. 운영 담당자와 함께 평가용 공식 연동 경로 A로 6단계 검증 기록표를 채우고, 필드 매핑·중복 처리·필수값 규칙·대조 결과를 증빙과 함께 남깁니다. 결과: 6단계 검증표, 매핑표, 캡처/운영 노트 세트
4. 검증 결과를 반영해 가이드를 게시하거나, 필수 운영 정보가 미확인인 경우 게시 보류 사유와 잔여 확인 항목을 기록한 뒤 측정 등록을 완료합니다. 결과: 게시 URL 또는 보류 기록, 그리고 후속 측정 대상 등록

### 완료 조건

- SRC001·SRC002·SRC003·SRC004·SRC021·SRC022에 대한 재사용 판단이 모두 기록되어 있다.
- 최종 자산은 ‘웹사이트 문의→CRM 리드 자동 등록’ 과업을 직접 답한다.
