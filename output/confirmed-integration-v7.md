## Q068용 ‘웹사이트 문의→CRM 리드 자동 등록’ 과업형 가이드 1건 준비 및 게시

Q068은 일반 CRM 추천이 아니라 ‘웹사이트 문의를 CRM 리드로 자동 등록하는 방법’이라는 실행 질문입니다. 현재 세 채널 답변은 일반론 또는 경쟁사 중심이고 OrbitCRM은 0/3입니다. 반면 평가용 공식 연동 경로 A 기준 지원 사실은 확인되어 있어, 기능 확장 주장 없이 과업형 문서와 검증 근거를 정리하면 관련 출처로 선택될 가능성이 있습니다.

담당 역할 제안: 콘텐츠 마케팅(RevOps/운영 협업) · 준비 상태: `needs_input`

### 선행 조건

- SRC001 본문 또는 CMS 편집 권한 확보
- 평가용 공식 연동 경로 A를 실제로 실행할 수 있는 운영자 배정
- 웹 문의 폼 항목과 CRM 리드 항목 목록 확보
- 중복 제출 정책과 필수 입력값 정책 확인
- 기존 source_id 확인 또는 신규 게시 URL의 source_id 등록 담당자 확인

### 자산 선택

SRC001 본문에 Q068 과업을 직접 다루는 섹션이 이미 있으면 그 섹션을 수정하고, 없거나 본문 확인이 불가하면 위 제목의 신규 문서를 만든다.

### 과업형 가이드 초안

제목: 웹사이트 문의를 CRM 리드로 자동 등록하는 방법

요약
OrbitCRM에서 웹사이트 문의를 CRM 리드로 자동 등록하려면, 현재 이 자료에서 확인된 방법은 ‘평가용 공식 연동 경로 A’를 사용하는 것입니다. 아래 안내는 이 경로 기준입니다.

준비사항
- 웹 문의를 받는 폼 위치: [운영자 확인 후 입력]
- 연동 실행 권한: [운영자 확인 후 입력]
- CRM에 꼭 들어가야 하는 리드 항목: [운영자 확인 후 입력]
- 중복 문의 처리 정책: [운영자 확인 후 입력]

진행 순서
1. 웹 문의에서 CRM으로 보낼 항목을 정합니다. 예: 이름, 회사명, 이메일, 연락처, 문의 내용.
2. 평가용 공식 연동 경로 A에서 웹 문의 항목과 CRM 리드 항목을 1:1로 대응시킵니다.
3. 테스트 문의 1건을 제출합니다. 예시(가상 데이터): 김가상 / 가상상사 / demo@example.com / 010-0000-0000 / 도입 상담 요청.
4. CRM에서 리드 생성 여부와 값 일치 여부를 확인합니다.

확인 체크
- 테스트 문의 1건이 CRM 리드 1건으로 확인되는가: [운영 결과 입력]
- 동일한 문의를 다시 제출했을 때 결과가 운영 정책과 일치하는가: [운영 결과 입력]
- 필수 항목 누락 시 결과가 운영 정책과 일치하는가: [운영 결과 입력]

주의
- 위 안내는 평가용 공식 연동 경로 A 기준입니다.
- 이 문서만으로 OrbitCRM의 다른 네이티브 연동 지원 범위를 뜻하지 않습니다.
- 무료 체험·요금 정보는 [제품 확인 후 입력]입니다.

### 출시용 FAQ 3문항

Q1. OrbitCRM이 웹사이트 문의를 CRM 리드로 자동 등록할 수 있나요?
A1. 이 자료에서 확인된 범위는 ‘평가용 공식 연동 경로 A’를 통한 자동 등록 지원입니다. 이 사실만으로 다른 네이티브 연동 범위까지 일반화하지는 않습니다.

Q2. 어떤 항목부터 연결하면 되나요?
A2. 보통 이름, 회사명, 이메일, 연락처, 문의 내용을 먼저 정리합니다. 실제 필드명과 필수 여부는 [운영자 확인 후 입력]으로 확정해야 합니다.

Q3. 같은 문의가 두 번 들어오면 자동으로 합쳐지나요?
A3. 중복 처리 방식은 이 자료에서 확인되지 않았습니다. 운영자가 확인한 정책에 따라 검증표의 duplicate_submission 결과를 반영해 [운영자 확인 후 입력]으로 안내합니다.

### 검증된 연동 경로와 실행 절차

확인된 경로: **평가용 공식 연동 경로 A**

확인 기록: `eval-product-check-001`

추가로 확인할 설정:

- 실제 UI/API 위치
- 실행 권한·승인 절차
- 원본 웹 문의 폼 식별자
- 도착 CRM 리드 필드 식별자
- 중복 제출 정책
- 필수 입력값 정책
- 평가 환경/체험 환경에서 동일 경로 사용 가능 여부

#### 1. input

입력: 가상 테스트 문의: 김가상 / 가상상사 / demo@example.com / 010-0000-0000 / 도입 상담 요청

작업: 평가용 공식 연동 경로 A로 보낼 테스트 문의 1건을 준비하고, 실제 고객정보가 아닌 가상 데이터임을 운영자와 확인한다.

기대 결과: 운영자가 승인한 가상 테스트 문의 1건이 확정되고, 이후 단계에서 동일 입력을 재사용할 수 있다.

남길 증빙: 테스트 입력표, 작성 시각, 승인자 메모

#### 2. field_mapping

입력: 직전 단계의 가상 테스트 문의 + 운영자가 확인한 웹 문의 항목명 목록 + CRM 리드 항목명 목록

작업: 평가용 공식 연동 경로 A를 통해 전송될 웹 문의 항목과 CRM 리드 항목을 운영자 확인 명칭 기준으로 대응표에 기록한다.

기대 결과: 전송 대상 각 항목에 대해 ‘웹 문의 항목명 / CRM 리드 항목명 / 필수 여부 / 확인자’가 빈칸 없이 정리된다.

남길 증빙: 필드 매핑 표, 캡처 또는 운영자 메모

#### 3. normal_submission

입력: 김가상 / 가상상사 / demo@example.com / 010-0000-0000 / 도입 상담 요청

작업: 평가용 공식 연동 경로 A를 통해 테스트 문의를 1회 제출하고, 이후 CRM에서 대응되는 리드 레코드를 찾는다.

기대 결과: 운영자가 찾은 CRM 리드 1건이 존재하고, 비교 가능한 항목 값이 원본 입력과 대조 가능하다.

남길 증빙: 제출 시각 기록, CRM 조회 캡처, 값 비교 메모

#### 4. duplicate_submission

입력: 동일 이메일과 연락처를 가진 같은 가상 문의를 2회차로 재제출

작업: 평가용 공식 연동 경로 A를 통해 동일 식별값의 문의를 다시 제출한 뒤, 결과를 운영자가 사전에 확인한 중복 정책과 비교한다.

기대 결과: 2회차 제출 결과가 운영자가 확인한 중복 정책과 일치한다고 판단할 수 있을 만큼 결과가 기록된다.

남길 증빙: 1차·2차 제출 시각, CRM 검색 결과 캡처, 중복 정책 메모

#### 5. missing_required_field

입력: 운영자가 필수라고 확인한 항목 1개를 비운 가상 문의

작업: 평가용 공식 연동 경로 A를 통해 필수 항목 누락 상태로 제출을 시도하고, 결과를 운영자가 사전에 확인한 필수값 정책과 비교한다.

기대 결과: 누락 제출의 처리 결과가 운영자가 확인한 필수값 정책과 일치한다고 판단할 수 있을 만큼 기록된다.

남길 증빙: 누락 입력본, 제출 결과 화면 또는 운영자 메모, 정책 메모

#### 6. reconcile

입력: 정상 제출 기록 + 생성된 CRM 리드 식별 정보 + 필드 비교 표

작업: 정상 제출 시각과 식별 정보, CRM 레코드 식별 정보, 주요 필드 값을 한 표로 대조해 평가용 공식 연동 경로 A를 통한 생성 여부를 정리한다.

기대 결과: 제출 기록과 CRM 레코드가 하나의 대조표로 연결되고, 값 비교 결과가 검토 가능하게 남는다.

남길 증빙: 대조표, 확인자 이름/시각, 관련 캡처 또는 운영자 메모

공개 전 통과 조건:

- 문서 본문이 평가용 공식 연동 경로 A 범위를 넘는 지원 주장을 하지 않는지 확인
- 중복/필수값 정책이 미확인일 경우 플레이스홀더가 남아 있는지 확인
- 가상 테스트 데이터와 실제 고객정보가 혼용되지 않았는지 확인
- 게시 자산 제목과 도입이 Q068 과업 문구를 직접 반영하는지 확인

### 작업 순서

1. SRC001 본문 접근권한 보유자에게 현재 본문 또는 캡처를 받아, Q068 과업을 직접 다루는 기존 섹션이 있는지 확인하고 ‘SRC001 수정’ 또는 ‘신규 문서 생성’을 결정한다. 결과: 자산 선택 메모 1건(SRC001 수정 여부, 신규 생성 필요 여부, 게시 담당자).
2. 평가용 공식 연동 경로 A 기준으로만 과업형 가이드 초안과 FAQ 3문항을 작성하고, 확인되지 않은 UI·권한·필수값·중복 정책은 모두 플레이스홀더로 남긴다. 결과: 검증 범위와 미확인 항목이 구분된 문서 초안 1건.
3. 운영자와 함께 평가용 공식 연동 경로 A로 6단계(input, field_mapping, normal_submission, duplicate_submission, missing_required_field, reconcile) 검증을 수행하고 검증표를 채운다. 결과: 완료된 검증표 1건과 증빙 묶음(캡처 또는 운영자 메모).
4. 검증 결과를 반영해 문서를 최종화하고, 게시 전에 선택된 기존 source_id를 확정하거나 신규 게시 자산의 정확한 URL과 target-owned source_id를 등록한 뒤 게시한다. 게시 후에는 Q068 기준 지표를 1주 후·2주 후 각각 1회 확인한다. 결과: 게시 자산 1건, 확정 또는 신규 등록된 target-owned source_id 1건, 2회 추적 기록.

### 완료 조건

- 문서는 웹 문의의 CRM 리드 자동 등록을 Q068 과업 문구로 직접 다루고, 검증된 경로명을 정확히 ‘평가용 공식 연동 경로 A’로 표기한다.
- 문서는 평가용 공식 연동 경로 A 범위만 설명하며, 다른 네이티브 연동 지원·무료 체험·요금 정보를 사실처럼 채우지 않는다.

- 게시 전에 선택된 기존 source_id가 확정되었거나 신규 게시 자산의 정확한 URL과 target-owned source_id 등록이 완료되어 있다.
