# 추천 흐름과 계약

[ProductAgent](../../src/vivi_agent/product.py)가 운영 진입점이다. API의 초안 요청과 기본 CLI `analyze`가 같은 클래스를 사용한다.

```text
load → policy → cache → generate → validate
          │       │        │          │
          └───────┴────────┴────────── 종료
```

`load`는 근거·지표·관계와 우선순위를 준비한다. `policy`는 현재 액션을 읽어 이미 진행 중인 질문을 제외한다. 수집률이 80% 미만이면 `insufficient_evidence`, 모든 유효 응답에서 추천되거나 새 과업이 없으면 `no_action`으로 끝난다.

`cache`는 정확히 같은 요청의 원문 초안을 다시 검증한다. 키에 고객, 데이터·맥락·정책·구현·스키마 버전, 선정 질문, 현재 액션, 모델 설정이 들어간다. 유사한 질문의 결과를 돌려주는 검색 캐시는 없다. 주석만 바꿔도 포함된 소스 파일의 해시가 달라지면 기존 캐시 키와 달라진다.

`generate`는 과제 호출 원장과 실제 비용 원장에 예약한 뒤 한 번 호출한다. 키 미설정, 예산 부족, 이전 실패, 생성 오류는 추가 호출 없이 `fallback`이 된다. `validate`는 구조·근거·선정 조건을 검사하고 실행·측정 계약을 생성한다. 실패한 초안을 모델에 다시 보내 고치는 루프는 운영 경로에 없다.

| 모듈 | 책임 |
| --- | --- |
| [compact.py](../../src/vivi_agent/compact.py) | 모델 입력·출력 계약, 표 형식 근거 인코딩·복원, 전체 계획 확장 |
| [selection.py](../../src/vivi_agent/selection.py) | 같은 질문의 후보 비교, 단일 선정, 전제 조건 이관, 주요 지표 정렬 |
| [models.py](../../src/vivi_agent/models.py) | 계획·작업·자산·산출물·연동 절차의 공통 타입 |
| [validation.py](../../src/vivi_agent/validation.py) | 허용 결정, 근거 ID, 지표·채널·자산 참조 검사 |
| [integration.py](../../src/vivi_agent/integration.py) | 확인된 연동 경로와 영수증, 6단계 절차 검사 |
| [execution_policy.py](../../src/vivi_agent/execution_policy.py) | 자산 검사·선정·게시·수집 조건 생성 |
| [measurement.py](../../src/vivi_agent/measurement.py) | 고정 질문/채널 표본, 분자·분모, 후속 측정 규칙 생성 |

모델은 후보 3개의 기대 이점, 노력의 가정, 실행 가능성, 전제, 위험, 선정·배제 이유를 작성한다. 선택한 후보에는 담당자, 실제 편집 가능한 초안, 작업 순서, 완료 기준을 붙인다. 제품 기능과 본문 내용은 근거로 확인된 범위만 쓴다. `false`로 확인된 기능을 `unknown`으로 되돌리거나 미확인 수동 경로로 대체하면 품질 실패다.

내용 작업에서는 전체 재사용 후보에 같은 필수 기준을 모두 적용한다. 실패 후보를 개정하지 않으며, 모든 후보의 검사를 끝내고 통과 후보가 없을 때만 새 자산을 만든다. `supporting_only` 자료는 편집·최종 인용 추적 대상에 넣지 않는다. 공개 원고의 미확정 주장은 확정하거나 삭제하고, 핵심 정보가 남으면 게시를 보류한다.

내용을 게시한 뒤에는 정확한 URL, 그 URL을 가리키는 자사 `source_id`, 확정 게시일시를 모두 기록해야 수집을 시작한다. 주요 지표는 선정 질문의 언급·추천이며 인용은 보조다. D7/D14의 고정 페어를 유지하고 결측을 0으로 바꾸지 않는다. 보조 지표만 좋아져도 성공으로 처리하지 않는다.

`operational` 작업은 내부 검증 결과와 근거 기록으로 완료 여부를 판단한다. 게시와 노출 수집은 적용하지 않으며 `context_baseline_only`로 현재 수치를 맥락 정보로만 표시한다.

[graph.py](../../src/vivi_agent/graph.py)의 `AgentRunner`는 별도 심화 검토 경로다. CLI의 `--deep-review`와 `evaluate`가 사용하며 진단·생성·검토·수정으로 여러 번 호출할 수 있다. 운영 1회 경로의 품질·비용 근거와 섞지 않는다.

변경 영향: 후보 필드를 바꾸면 `compact.py`, `selection.py`, 프런트 타입·비교 화면을 함께 확인한다. 실행 분기나 측정 문구는 모델 자유 텍스트보다 계약 생성기에서 먼저 고친다. 프롬프트를 바꾸면 스키마 테스트만으로 끝내지 않고 [고정 품질 사례](../validation/guide.md)를 다시 검토한다.
